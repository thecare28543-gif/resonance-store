# ตั้งค่าฐานข้อมูล PostgreSQL + ระบบล็อกอิน (Resonance Store)

ตั้งแต่เวอร์ชัน 2026.11.11 ข้อมูลทั้งหมดของเว็บเก็บใน **PostgreSQL** และทุกคนต้อง **ล็อกอิน** ก่อนเข้าเว็บ: User = เลข GID ของตัวเอง, Password = เลข GID เดิมอีกครั้ง

## สิ่งที่ต้องมีบนเครื่อง server
- Node.js 18 ขึ้นไป
- PostgreSQL 13 ขึ้นไป (ทดสอบแล้วกับ 18) และ pgAdmin 4
- ไฟล์เว็บทั้งโฟลเดอร์ รวม `db\`, `login.html`, `users.html`, `package.json`

## ขั้นที่ 1 · สร้างผู้ใช้ฐานข้อมูลและฐานข้อมูล (pgAdmin)
1. เปิด pgAdmin 4 แล้วเชื่อมต่อด้วย `postgres`
2. คลิกขวาที่ฐานข้อมูล `postgres` → **Query Tool**
3. เปิดไฟล์ `db\01_create_user_and_db.sql`
4. เปลี่ยน `'เปลี่ยนเป็นรหัสที่ปลอดภัย'` เป็นรหัสจริง แล้วจดไว้ใช้ในขั้นที่ 3
5. กด **Execute (F5)** จะได้ผู้ใช้ `rs_app` และฐานข้อมูล `resonance_store`

## ขั้นที่ 2 · สร้างตาราง (pgAdmin)
1. กด F5 รีเฟรชรายการ แล้วคลิกขวาที่ `resonance_store` → **Query Tool**
2. พิมพ์บรรทัดนี้ไว้บรรทัดแรก เพื่อให้ตารางเป็นของ `rs_app`:
   ```sql
   SET ROLE rs_app;
   ```
3. เปิดไฟล์ `db\schema.sql` (หรือก๊อปเนื้อหาต่อจากบรรทัดแรก) แล้วกด **Execute (F5)**
4. ดูใน `resonance_store → Schemas → public → Tables` จะเห็น 14 ตาราง และใน Views จะเห็น 3 view

> ถ้าข้ามขั้นที่ 2 ไป server จะสร้างตารางให้เองตอนเปิดครั้งแรก ใช้ไฟล์เดียวกัน
> รัน `schema.sql` ซ้ำได้ ไม่ทำให้ข้อมูลเสีย

## ขั้นที่ 3 · ตั้งค่า server
1. ก๊อป `server-config.example.json` เป็น `server-config.json`
2. ใส่รหัสของ `rs_app` ในช่อง `"password"`
3. เปิด Command Prompt ในโฟลเดอร์เว็บ แล้วรัน:
   ```
   npm install
   node server.js
   ```
   คำสั่งแรกลงตัวเชื่อมฐานข้อมูล `pg` ให้ (ทำครั้งเดียว)

ข้อมูลเดิม: ถ้ามีไฟล์ `data\resonance-data.json` จากเวอร์ชันก่อน server จะย้ายเข้า PostgreSQL ให้เองตอนเปิดครั้งแรก และเก็บ Backup ไว้ 1 ชุด

| ช่องใน server-config.json | ความหมาย |
|---|---|
| `database` | ที่อยู่ฐานข้อมูล: host, port, database, user, password (หรือใช้ตัวแปร `DATABASE_URL` แทน) |
| `sessionHours` | ล็อกอินอยู่ได้กี่ชั่วโมง ค่าเริ่ม 12 (1 กะ) |
| `secureCookie` | `"auto"` = ใส่ Secure เองเมื่อเปิดผ่าน https (ผ่าน reverse proxy ที่ส่ง `X-Forwarded-Proto`) |
| `backupDir` | โฟลเดอร์สำเนา Backup เพิ่ม เช่น SharePoint ของทีม (ไม่บังคับ) |
| `keepDays` | เก็บ Backup กี่วัน (ใหม่สุด 10 ชุดเก็บเสมอ) |

## ขั้นที่ 4 · สร้างแอดมินคนแรก
1. ดู log ตอนเปิด server จะมีบรรทัด `NO ADMIN YET ... setup code: xxxxx` (เก็บไว้ในไฟล์ `data\setup-token.txt` ด้วย)
2. เปิดเว็บ ระบบจะพาไปหน้า **ตั้งค่าครั้งแรก**
3. ใส่ setup code, GID และชื่อของแอดมิน (แอดมินเข้าระบบด้วย GID / GID เหมือนทุกคน)
4. ระบบเข้าหน้า **จัดการผู้ใช้งาน** (`users.html`) ให้เลย
5. หลังมีแอดมินแล้ว setup code ใช้ไม่ได้อีก และไฟล์ `setup-token.txt` ถูกลบเอง

## เพิ่มผู้ใช้ (หน้า จัดการผู้ใช้งาน)
- **เพิ่มทีละคน:** ใส่ GID, ชื่อ, สิทธิ์, กะ แล้วบอกผู้ใช้ว่าเข้าด้วย **GID / GID** ไม่ต้องแจกรหัส
- **นำเข้า Excel / CSV:** มีคอลัมน์ `GID`, `Name` หรือ `ชื่อ`, `Role` หรือ `สิทธิ์`, `Crew` หรือ `กะ`, `Department` หรือ `แผนก`
  - กดปุ่ม "ไฟล์ตัวอย่าง" เพื่อดาวน์โหลดแบบฟอร์ม
- **ผู้ใช้เข้าครั้งแรก:** ใช้ GID / GID ได้ทันที ไม่ต้องตั้งรหัส (กติกาของแลป เลือกเมื่อ 11 พ.ย. 69)
- **ใส่ผิดจนบัญชีล็อก:** แอดมินกด "🔓 ปลดล็อก" ในตารางผู้ใช้ได้ทันที
- **คนลาออก / ย้ายแผนก:** กด "ปิดบัญชี" แทนการลบ เพื่อให้ประวัติว่าใครแก้อะไรยังอยู่

## สิทธิ์ 3 ระดับ
| | Admin | User | Viewer |
|---|:-:|:-:|:-:|
| ดูผัง 3D / 2D, ค้นหา, รายงาน | ✔ | ✔ | ✔ |
| รับงาน / หยิบงาน / ย้าย / Hold / นำเข้าไฟล์ / Data Entry | ✔ | ✔ | — |
| กด Backup ตอนนี้ | ✔ | ✔ | — |
| กู้คืน Backup | ✔ | — | — |
| จัดการผู้ใช้ | ✔ | — | — |

ระบบต้องมีแอดมินที่ใช้งานอยู่อย่างน้อย 1 คนเสมอ และแอดมินลดสิทธิ์หรือปิดบัญชีตัวเองไม่ได้

## ความปลอดภัยที่มีให้แล้ว
- รหัสผ่าน (= GID) เก็บแบบเข้ารหัสทางเดียว (scrypt)
- ⚠ ข้อจำกัดของ GID / GID: คนที่รู้ GID ของคนอื่น (เช่นเห็นบนบัตรพนักงาน) เข้าแทนได้ จึงให้ทุกคนกด "ออกจากระบบ" ก่อนลุกจากเครื่อง และแอดมินดูประวัติเข้าระบบได้ในหน้าจัดการผู้ใช้
- ใส่รหัสผิด 5 ครั้ง บัญชีล็อก 15 นาที และถ้าเครื่องเดียวกันผิด 20 ครั้งใน 15 นาที ระบบจะพักเครื่องนั้น
- คุกกี้ล็อกอินเป็น HttpOnly + SameSite=Strict (และ Secure เมื่อใช้ https) อายุ 12 ชั่วโมง
- การบันทึกข้อมูลต้องมี header พิเศษจากหน้าเว็บของเราเท่านั้น จึงกันเว็บอื่นแอบส่งคำสั่งแทน (CSRF)
- ไฟล์ตั้งค่า, `db\`, `data\`, `node_modules\` และไฟล์ .xlsx / .csv / .pptx เปิดผ่านเว็บไม่ได้
- ทุกการเข้าระบบเก็บใน `login_log` และทุกการแก้ผู้ใช้เก็บใน `user_admin_log`
- ชื่อผู้แก้ไข (Last_Editor) ใช้ชื่อจากการล็อกอิน และ `rs_kv.updated_by` เก็บ GID ของคนที่บันทึก

## ตารางในฐานข้อมูล
| ตาราง | เก็บอะไร |
|---|---|
| `app_users` | ผู้ใช้: GID, ชื่อ, สิทธิ์, กะ, แผนก, ใช้งานหรือไม่, รหัสผ่าน (hash), เข้าล่าสุด |
| `user_sessions` | การล็อกอินที่ยังไม่หมดอายุ |
| `login_log` | ประวัติเข้าระบบ (สำเร็จ / ไม่สำเร็จ / ออกจากระบบ) |
| `user_admin_log` | ใครเพิ่ม / แก้ / ตั้งรหัสให้ใคร |
| `rs_meta` | เลขเวอร์ชันข้อมูล (เพิ่มทุกครั้งที่บันทึก) |
| `rs_kv` | **ข้อมูลหลัก** ของเว็บ เป็นชุดข้อมูล JSON ต่อ key เช่น `resStoreV7` (Store), `jobDetailV7` (Job Detail), `resHoldV1` (Hold) |
| `rs_backups` | Backup อัตโนมัติ รายชั่วโมง, ทุกเปลี่ยนกะ, กดเอง, ก่อนกู้คืน, บันทึกชนกัน |
| `store_rows` | สำเนาอ่านง่าย: งานบนชั้นทีละแถว (Rack, Side, ชั้น, IN/OUT, Job, จำนวน, Tester) |
| `jobs` | สำเนาอ่านง่าย: Job Detail (Owner, Product, สถานะ, ทุกคอลัมน์ใน `detail`) |
| `holds` | สำเนาอ่านง่าย: งานที่ติด Hold อยู่ |
| `hold_log` | สำเนาอ่านง่าย: ประวัติ Hold / ปลด / ถูกกัน |
| `dispose_decisions` | สำเนาอ่านง่าย: คืน Owner / Scrap / Pending |
| `zones` | สำเนาอ่านง่าย: ผังโซน |
| `training_attempts` | สำเนาอ่านง่าย: ผลอบรม |

| View | ใช้ดู |
|---|---|
| `v_position_load` | จำนวนชิ้นต่อช่อง และสถานะ NORMAL / WARNING / OVER LIMIT |
| `v_jobs_in_store` | งานในชั้น พร้อม Owner, สถานะ, ตำแหน่ง, ติด Hold ไหม |
| `v_users` | รายชื่อผู้ใช้ (ไม่มีรหัสผ่าน) |

> **ตาราง "สำเนาอ่านง่าย" อย่าแก้ด้วยมือ** server สร้างใหม่จาก `rs_kv` ทุกครั้งที่มีการบันทึก ให้แก้ข้อมูลในหน้าเว็บ
> ใช้ตารางเหล่านี้ทำรายงาน, Power BI หรือ query ใน pgAdmin ได้เลย เช่น:
> `SELECT * FROM v_jobs_in_store WHERE on_hold;`

## Backup ของฐานข้อมูลทั้งก้อน
นอกจาก `rs_backups` แล้ว ควรให้ IT / Dev ตั้ง `pg_dump` ทุกวันไปเก็บนอกเครื่อง:
```
pg_dump -U rs_app -d resonance_store -F c -f resonance_store_YYYYMMDD.backup
```
กู้คืนด้วย `pg_restore` หรือคลิกขวาที่ฐานข้อมูลใน pgAdmin → **Restore**
