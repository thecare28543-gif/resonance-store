# ชุดทดสอบอัตโนมัติ (Automated tests)

รันทุกครั้งก่อนปล่อยเวอร์ชันใหม่ · ทดสอบกับ **PostgreSQL ชั่วคราว** ที่สร้างขึ้นเองแล้วลบทิ้ง **ไม่แตะฐานข้อมูลจริง** · ข้อมูลในการทดสอบเป็นข้อมูลสมมติทั้งหมด

## ต้องมี
- Node.js 18+, Microsoft Edge, PostgreSQL 13+ (ใช้แค่โปรแกรมใน `bin\` เช่น initdb, pg_ctl, psql)
- รัน `npm install` 1 ครั้งใน `app\` และใน `tests\`

## วิธีรัน
```
powershell -ExecutionPolicy Bypass -File tests\run-tests.ps1
```
ถ้า PostgreSQL ไม่ได้อยู่ที่ `C:\Program Files\PostgreSQL\18\bin` ให้ใส่ `-PgBin "<path>"` · port ทดสอบค่าเริ่ม 55432 (`-Port`)

## มีอะไรบ้าง

| ไฟล์ | ทดสอบ | จำนวนข้อ (11 พ.ย. 2569) |
|---|---|---|
| `auth_api.js` | API: ล็อกอิน GID/GID, setup แอดมินคนแรก, สิทธิ์ admin/user/viewer, ล็อกบัญชี 5 ครั้ง, ปลดล็อก, ปิดบัญชี, นำเข้าผู้ใช้, CSRF, ไฟล์ที่ต้องห้ามเปิด, บันทึก/ชน 409, ตารางรายงานใน PostgreSQL, Backup แรก | 43 |
| `e2e.js` | 2 เครื่องล็อกอินพร้อมกัน: ซิงก์, บันทึกชน (เพิ่ม/ลบ/แก้ค้าง), Undo/Redo เฉพาะเครื่องตัวเอง, เตือนเครื่องเวอร์ชันเก่า, เกิน 80 ชิ้น, กัน Hold ทุกทาง, Import/Reset เก็บงาน Hold, Export รายสัปดาห์, ไม่มี error | 24 |
| `ui_login.js` | หน้าจอจริง: หน้า Login (ธีม/โหมดมืด/มือถือ), setup, รหัสผิด, หน้าบัญชีผู้ใช้ (เพิ่ม/นำเข้า/เปลี่ยนสิทธิ์/ประวัติ), Viewer บันทึกไม่ได้, ออกจากระบบ + ภาพหน้าจอ | 14 |

ผลที่ถูกต้อง: ทุกไฟล์ขึ้น `--- N pass · 0 fail` · บรรทัด `TargetClosedError` หลังสรุปของ e2e เป็นเรื่องของตัวทดสอบตอนปิดเบราว์เซอร์ ไม่ใช่บั๊กของเว็บ

## เมื่อแก้โค้ด
- เพิ่มฟีเจอร์ → เพิ่มข้อทดสอบในไฟล์ที่เกี่ยวข้อง (รูปแบบ `check('ชื่อ', เงื่อนไข, ข้อมูลประกอบ)`)
- ข้อไหน FAIL ให้หาสาเหตุก่อนว่าเว็บพังหรือตัวทดสอบล้าสมัย · ห้ามแก้ข้อทดสอบให้ผ่านโดยไม่เข้าใจสาเหตุ
- ห้ามใส่ GID / ชื่อจริงของพนักงานในไฟล์ทดสอบ
