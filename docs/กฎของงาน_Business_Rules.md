# กฎของงาน (Business Rules) · Resonance Store

เอกสารนี้อธิบาย **ว่าระบบทำอะไร และทำไม** ก่อนแก้โค้ดส่วนไหน ให้อ่านกฎของส่วนนั้นก่อน · ตัวเลขทุกตัวมาจากค่าคงที่ใน `app.js` (ชื่ออยู่ในวงเล็บ) ถ้าจะเปลี่ยน ให้ถามเจ้าของกระบวนการ (หัวหน้าแลป / ทีม Kaizen) ก่อน

## 1. งานของแลปที่ระบบรองรับ

1. ทีมทดสอบทดสอบเสร็จที่เครื่อง **Tester 01 / 02 / 03** (`TESTERS` = T1–T3)
2. นำถาดงานมาวางบนชั้นใน Store เพื่อ **Hold รอผลจากแลป** ← **ขั้นที่ระบบนี้ปรับปรุง**
3. ผลออก → **คืนเจ้าของงาน (Owner)** หรือ **Scrap**

ปัญหาเดิมที่ระบบแก้: หางานนาน 20–30 นาที, หาไม่เจอ, และงาน Hold ถูก Scrap ผิด เป้าหมายคือ **ถูกที่ · ถูกงาน · ถูกเวลา**

## 2. ผังชั้นวาง (คงที่ ไม่ได้มาจากข้อมูล)

| เรื่อง | กฎ |
|---|---|
| ตำแหน่งทั้งหมด | 2 Rack (A, B) × 2 ด้าน (L, R) × 3 ชั้น × 2 ช่อง (IN, OUT) = **24 ตำแหน่ง** (`RACK_SIDES`, `FLOORS_N`, `CELLS_N`) |
| ด้าน | **L = ฝั่งทางเดิน (หน้า)** · **R = ฝั่งผนัง (หลัง)** — Rack B ใช้กฎเดียวกันเมื่อมองจากทางเดิน |
| ชั้น | ชั้น 1 = ล่างสุด · ชั้น 2 = ระดับเอว (หยิบง่ายที่สุด) · ชั้น 3 = บน |
| ช่อง | OUT = ครึ่งฝั่ง T1 · IN = ครึ่งฝั่งหลังห้อง |
| การเดิน | A-R และ B-L เข้าจากทางเดิน · A-L เข้าจากหลัง Rack A · B-R เข้าจากด้านไกลของ Rack B (คำนวณใน `walkPath`) |

ถ้า Store อื่นมีผังต่างจากนี้ ต้องแก้ค่าคงที่และ 3D (`GEO`) — ระบบยังไม่รองรับผังแบบตั้งค่าได้

## 3. ความจุ

| กฎ | ค่า |
|---|---|
| ต่อตำแหน่ง รวมทุกงาน | **ไม่เกิน 80 ชิ้น** (`LIMIT`) — ฟอร์มรับงาน, Data Entry, การย้าย และ Smart slot **ไม่ยอมบันทึก** ถ้าเกิน |
| เตือน (WARNING) | ตั้งแต่ **60 ชิ้น** (`WARN_AT`) |
| ใกล้เต็ม (แจ้งทีม) | ตั้งแต่ 75% ของ 80 (`NEAR_FULL_RATIO`) |
| ถาด | IM = 8 ชิ้น/ถาด · FOF = 32 ชิ้น/ถาด · อื่น ๆ นับ 8 ชิ้น/ถาด |
| ถาดต่อโซน | 4 ตั้ง × สูง 4 ถาด = **16 ถาด** (`STACKS_PER_ZONE`, `TRAYS_PER_STACK`) |
| ลำดับวางถาด | ตั้งนับจาก **ซ้าย** เมื่อยืนหน้าชั้น · ถาดนับจาก **ล่าง** · เต็มตั้งหนึ่ง (4 ถาด) แล้วไปตั้งถัดไป · ฟอร์มแสดงภาพ ★ ถาดแรก |

## 4. โซน (Zone)

- แต่ละตำแหน่งผูกกับ **Product** และ **Type** ได้ (`resZoneV1`) · ไม่ผูก = รับทุกงาน · `*` = ทุกค่า
- วางงานผิดโซน → **ไม่บันทึก** และนับเป็น "ระบบกันความผิดพลาด" (kind = zone)
- ตำแหน่งที่เป็น **โซน HOLD** รับเฉพาะงานที่ติด Hold · ถ้ามีโซน HOLD งาน Hold ต้องไปอยู่ในโซนนั้น
- ติด / ปลด Hold แล้วงานอยู่ผิดโซน → ระบบหาช่องที่ถูกและย้ายให้ (`findZoneFor`, `moveJobTo`) แล้วเตือนให้ย้ายถาดจริงตาม
- ติดตั้งใหม่เริ่มแบบ **ไม่มีโซน** · ผังโซนที่แนะนำของแลป (`RECOMMENDED_ZONES`) โหลดได้จากปุ่ม "คืนค่าผังโซนแนะนำ" เท่านั้น

## 5. Hold (งานห้ามทิ้ง)

| กฎ | รายละเอียด |
|---|---|
| ติด Hold | ต้องใส่ **ชื่อผู้สั่ง + เหตุผล** |
| ปลด Hold | ต้องมี **ผู้อนุมัติ + เหตุผล** |
| ระบบกัน 3 ทาง | งาน Hold **Scrap ไม่ได้ · หยิบออกไม่ได้ · ลบไม่ได้** |
| กันเพิ่ม | แก้ Job No. / จำนวน / ตำแหน่ง ใน Data Entry ไม่ได้ (แถวสีแดง ช่องล็อก) · Undo/Redo ที่จะเปลี่ยนงาน Hold ไม่ทำ · Reset และ Import ไม่ลบงาน Hold |
| บันทึก | ทุกการติด / ปลด / ถูกกัน เก็บใน `resHoldLogV1` (action = block = หลักฐาน Poka-yoke) |
| ป้ายจริง | งาน Hold ต้องมี **ป้ายแดง HOLD** ที่ถาด |
| ตรวจทุกกะ (Roving audit) | ทุกกะต้องติ๊กว่างาน Hold ทุกงาน "อยู่ครบ + มีป้าย" (`resHoldAuditV1`) · ไม่พบ → แจ้งเตือนและนับเป็นปัญหา |
| 3 ด่านก่อน Scrap | ระบบเช็ก · ป้ายแดงที่ตัวงาน · ตรวจทุกกะ (เฟสถัดไป: สแกน QR ยืนยันก่อน Scrap) |

## 6. รับงานเข้า (ฟอร์ม "รับงานเข้า")

- ช่องบังคับ: **Job No., Type, จำนวน** · ตำแหน่ง Rack/Side/ชั้น/Cell · Tester ที่งานมาจาก · ชนิดถาด
- Job No. แปลงเป็นตัวพิมพ์ใหญ่ ลบช่องว่าง และ `-` → `_` (`normJob`) · `N/A`, `-`, `NONE` = ไม่ใช่ Job (ตัวอย่าง / Museum)
- **Smart slot (✦ แนะนำช่อง)** ให้คะแนนทุกช่องที่โซนรับและมีที่พอ แล้วเสนอ 3 อันดับ:
  - โซนเฉพาะ Product +25 · มี Job เดียวกันอยู่แล้ว +22 · ถาดชนิดเดียวกัน +6 · ชั้น 2 +8 · ชั้น 1 +2
  - ระยะเดินจาก Tester −4 ต่อเมตร · ยิ่งเต็มหลังวางยิ่งลด (สูงสุด −35) · หลังวางถึง 60 ชิ้น −25
- **Poka-yoke สแกน QR ก่อนบันทึก** มีในโค้ดแต่ **ยังไม่ใช้งาน** (รอเครื่องสแกนที่ผ่านกฎคลีนรูม)

## 7. หยิบงานออก (Pick List)

- เลือกงานที่จะคืน / Scrap → ระบบเรียง **เส้นทางเดินสั้นที่สุด** และไฮไลต์สีส้มบนจอ (pick-to-light บนจอ ชั้นจริงไม่มีไฟ)
- งาน Hold ติ๊กไม่ได้ · "นำออกจาก Store" จะลบแถวและบันทึกประวัติ

## 8. อายุงานใน Store

- นับจาก **Received Date** ใน Report.csv
- 7–13 วัน = เตือน (เหลือง) · **ตั้งแต่ 14 วัน = ค้าง (แดง)** แจ้งทีม และเสนอส่งอีเมลหา Owner (อีเมลเดาจากชื่อ ชื่อ.นามสกุล@seagate.com แก้ได้)

## 9. กะทำงาน

- 3 กะ **A / B / C** หมุน 12 วัน: เช้า 4 วัน · หยุด 2 · ดึก 4 · หยุด 2 (`SHIFT_PATTERN = DDDDOONNNNOO`)
- เช้า 06:00–18:00 · ดึก 18:00–06:00 · จุดอ้างอิง 4 ต.ค. 2569 (`SHIFT_BASE_DAY`, `SHIFT_BASE_IDX`)
- Backup อัตโนมัติทุกเปลี่ยนกะ · นับสต็อกแบบสุ่ม **3 ตำแหน่งต่อกะ** (`CC_PER_SHIFT`) แบบไม่ดูยอดในระบบ

## 10. วัดผล Kaizen (ข้อมูลจริงจากการใช้งาน)

| ตัวชี้วัด | เก็บจาก |
|---|---|
| เวลาค้นหาบนจอ | จับเวลาอัตโนมัติ ตั้งแต่เริ่มค้นจนเจอ (`kz.find`, 0.3 วิ – 5 นาที) |
| เวลารับงาน | จากเปิดฟอร์มถึงบันทึก (`kz.add`) |
| ก่อนปรับปรุง / หน้างานจริง | จับเวลาด้วยมือในหน้า Kaizen (`kz.base`, `kz.floor`) |
| หาไม่เจอ | ปุ่ม "✕ หาไม่เจอ" (`kz.miss`) |
| ระบบกันความผิดพลาด | ทุกครั้งที่ระบบปฏิเสธ (`kz.blocks`: hold / zone / over / poka / scrap / holdaudit / cycle …) |
| Export รายสัปดาห์ | 1 แถวต่อสัปดาห์ จันทร์–อาทิตย์ (`exportWeekly`) |

## 11. อบรม

- สอบ 10 ข้อ สุ่มจากคลัง · **ผ่าน ≥ 8/10** (`TRAIN_PASS = 0.8`) **และ** ผ่านภาคปฏิบัติครบ 5 ข้อ (ผู้สอนติ๊ก)
- เก็บทุกการสอบ แยกตามคนและกะ · พิมพ์ใบรับรองได้

## 12. ผู้ใช้และสิทธิ์

| สิทธิ์ | ทำได้ |
|---|---|
| Admin | ทุกอย่าง + จัดการบัญชีผู้ใช้ + กู้คืน Backup |
| User | งาน Store ทั้งหมด (รับ / หยิบ / ย้าย / Hold / นำเข้า / Data Entry / กด Backup) |
| Viewer | ดูอย่างเดียว (เว็บไม่บันทึก + server ปฏิเสธ) |

- ล็อกอิน: **User = GID, Password = GID** (กติกาแลป 11 พ.ย. 2569) · อยู่ได้ 12 ชม. (1 กะ)
- ชื่อผู้แก้ไข (`Last_Editor`) และประวัติทุกอย่าง ใช้ชื่อจากการล็อกอิน แก้เองไม่ได้
- ต้องมีแอดมินอย่างน้อย 1 คนเสมอ · แอดมินลดสิทธิ์/ปิดบัญชีตัวเองไม่ได้ · คนลาออก = ปิดบัญชี ห้ามลบ
- หน้า Login **ต้องไม่บอกอะไรเกี่ยวกับระบบ** (ไม่มีคำแนะนำ ไม่มีตัวอย่าง GID) และข้อความ error เป็นแบบกลาง ๆ

## 13. หลายเครื่องพร้อมกัน

- ทุกเครื่องเห็นข้อมูลเดียวกันภายใน ~5 วินาที
- สองเครื่องบันทึกชนกัน → **รวมทั้งสองฝั่ง** (3-way merge) ไม่มีของใครหาย · สำเนาก่อนรวมเก็บใน Backup (conflict)
- **Undo / Redo ย้อนเฉพาะงานที่เครื่องนี้ทำ** ไม่ลบงานที่เครื่องอื่นเพิ่มเข้ามา
- server ล่ม → ทำงานต่อจากสำเนาในเครื่อง แล้วส่งเองเมื่อกลับมา · ล่มนาน → ใช้ **ผังกระดาษ** ที่พิมพ์ทุกกะ
- เครื่องไหนใช้ไฟล์เว็บเก่า ระบบเตือนทุก 30 นาที → **ทุกครั้งที่ปล่อยเวอร์ชันใหม่ต้องเปลี่ยน `VER` ใน sync.js**

## 14. ข้อมูลที่นำเข้า

- **ไฟล์ Store (.xlsx/.csv):** หาแถวหัวตารางในทุก sheet เอง · ข้ามแถวที่มีแค่ตำแหน่ง · คอลัมน์ตาม `STORE_COLS` (สะกด `QUANITY` ตามไฟล์บริษัท ห้ามแก้)
- **Report.csv:** ~2,000 Job · จับคู่ด้วย Job No. ที่แปลงแล้ว · **นำเข้าใหม่จะทับข้อมูล Job ที่แก้เองในตาราง Jobs** (ดูรายการปัญหาที่รู้)
- Import ไฟล์ Store แทนที่ข้อมูลเดิม **ยกเว้นงาน Hold ที่ไม่มีในไฟล์ จะเก็บไว้**
- Export ส่งออกคอลัมน์บริษัท + `TESTER`, `TRAY` ต่อท้าย
