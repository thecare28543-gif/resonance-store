## B. ปัญหาที่รู้อยู่ (ยังไม่แก้)

| # | ปัญหา | ผลกระทบ | ทางแก้ที่เสนอ |
|---|---|---|---|
| B1 | **ล็อกอินด้วย GID / GID** | ใครรู้ GID คนอื่นเข้าแทนได้ → ชื่อผู้แก้ไขเชื่อถือได้น้อยลง | เป็นการตัดสินใจของแลป · ถ้าต้องการเข้มขึ้น: ใช้ SSO ของบริษัท หรือให้ผู้ใช้ตั้งรหัสผ่านเอง (ตาราง `app_users` รองรับอยู่แล้ว: `password_hash`, `must_change_password`) |
| B2 | นำเข้า Report.csv ใหม่ทับข้อมูล Job ที่แก้เอง | Owner / Product / Description / Test Status ที่แก้ในตาราง Jobs หายเมื่อ import ใหม่ | เก็บช่องที่แก้เองแยก (overrides) แล้วรวมตอนแสดง |
| B3 | พื้นที่ `localStorage` ของเบราว์เซอร์ (~5–10 MB) | ข้อมูลทุกชุดต้องพอดีในเครื่องลูก · ประวัติ Time Machine ใหญ่สุด (ตัดที่ ~3 MB / 180 วัน) | ระยะยาว: ให้เว็บดึงประวัติจาก server แทนเก็บทั้งหมดในเครื่อง |
| B4 | ส่งข้อมูลทั้งชุดทุกครั้ง | บันทึก 1 แถวก็ส่ง `resStoreV7` ทั้งชุด · ตอนนี้เล็ก (~40 แถว) ไม่มีปัญหา | ถ้าข้อมูลโตมาก: API แบบทีละแถว |
| B5 | `app.js` ไฟล์เดียว ~4,100 บรรทัด | แก้ยาก ชนกันง่ายเมื่อหลายคนแก้ | แยกเป็นโมดูลตาม `CODE_MAP.md` (ตัดสินใจไว้ว่าทำหลังงาน Kaizen) |
| B6 | ผังชั้นวางเขียนตายตัวในโค้ด | Store อื่นที่ผังต่างกันต้องแก้โค้ด (`RACK_SIDES`, `FLOORS`, `GEO`) | ทำผังเป็นค่าตั้ง (config) |
| B7 | เปิดไฟล์ HTML ตรง ๆ ได้ (โหมด local) | ไม่มีล็อกอิน ข้อมูลอยู่เครื่องเดียว | ใช้เฉพาะฉุกเฉิน · WI ให้เปิดผ่าน URL ของ server เท่านั้น |
| B8 | `must_change_password` ไม่ได้ใช้แล้ว | คอลัมน์ค้างใน `app_users` | ลบได้ในอนาคต (ต้องแก้ server.js ด้วย) |
| B9 | ชื่อ Tester | `TESTER_NAME` ใน app.js ยังว่าง (แสดงแค่ Tester 01/02/03) | ใส่ชื่อเมื่อแลปกำหนด |
| B10 | คู่มืออบรม (training manual) | ยังเป็นฉบับก่อนมีล็อกอิน | เพิ่มหน้าล็อกอินและบัญชีผู้ใช้ |
